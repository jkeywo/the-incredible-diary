# GitHub authored-project contract

The GitHub project consists of two files at one commit: `.incredible-diary/project.json` identifies the format and schema, and `.incredible-diary/scenario.json` contains the validated authored scenario. Background assets are embedded as checksummed base64 entries in the scenario, so each commit moves content and its references together. A repository without this exact manifest is not treated as a project. The packager rejects unknown top-level and nested authored fields before writing either file; game saves, recorded simulation history, local undo/redo, authoring drafts and credentials are never part of these files.

The repository reader resolves a branch to one commit before fetching its tree and blobs. This avoids combining files from two HEADs if the branch moves during download. Opening a project validates the manifest, JSON, authored references and embedded assets before returning content to the editor. The local authoring document stores its selected repository, branch, HEAD and baseline content for later three-way integration.

Commit creation writes blobs, a tree and a commit through the GitHub REST API, then updates the selected branch with `force: false`. A remote HEAD change blocks the operation; an uncertain final update checks the remote branch before reporting success. Edits made while preparing a commit prevent its branch update. Edits made during the branch update remain local and get an undo operation after the new HEAD is acknowledged. Fetch alone does not change local authoring history. Adoption of a new HEAD clears preceding undo/redo but retains combined uncommitted content. Invalid combinations become a saved, invalid scenario draft for repair, blocking resume and commit while leaving the previous applied content and HEAD intact.

When edits conflict, a valid local project can be committed on a deterministic `diary-conflict/…` branch. If the combined project is invalid, its draft remains saved for correction while the last valid local project can be preserved on that branch. A retry checks the existing branch and its content before reusing it. The editor can link to GitHub's comparison view for resolution, then fetch the resolved branch through the normal path.

The editor uses a token entered separately on each device. The web build stores it under this site's browser local storage; Windows stores it in Godot's per-user `user://github_credentials.json`. Removing the token clears local storage and in-memory API access without changing an open draft. The token is used only in GitHub API request headers; neither the repository project nor the web export contains it. The browser origin must be trusted because scripts on that origin can read its local storage. Real commit, merge and conflict tests require a designated writable test branch.

The chosen configuration uses a per-device fine-grained GitHub personal access token with repository Contents access to `jkeywo/the-incredible-diary`. No OAuth registration, client secret or authentication host is required. Test writes use `codex/sync-integration-test`; the branch is separate from `main`, which alone triggers the Pages deployment. The browser and Windows clients each receive the token through their own GitHub project panel. The token must not be placed in a command, source file, issue, save export or test fixture.
